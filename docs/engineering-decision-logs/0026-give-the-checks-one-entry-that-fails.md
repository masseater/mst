# 0026. 検査の入口を 1 つにし、報告が出たら落とす

- ステータス: Accepted
- 日付: 2026-08-11

## 文脈

`@mst/dont-review-it` の CLI は 4 つのサブコマンドを持っていた。`verify` / `equivalent-concepts` / `duplicated-bodies` / `workflows`。

このうち `guard` が呼んでいたのは 3 つで、`equivalent-concepts` は呼ばれていなかった。呼ぶ側が入口を選べる形になっていたので、検査を足したときに載せ忘れれば「実装はあるが誰も走らせない」状態がそのまま残る。[EDR 0022](0022-make-the-production-graph-a-required-gate.md) がゲートの定義を 1 つに畳んだのと同じ問題が、パッケージの中に残っていた。

もう 1 つ、より悪い形があった。`equivalent-concepts` と `duplicated-bodies` は、報告を出しても終了コード 0 で終わっていた。`duplicated-bodies` は `guard` に載っているので、重複した本体が実在しても `guard` は緑になる。[EDR 0013](0013-draw-the-duplication-line-at-decidability.md) は「報告が出たら必ず直す。緩める余地を設計に持たせていない」と書いており、終了コードがその設計と食い違っていた。`docs/guidelines/enforcement.md` が「設定に名前が出ることは、そのガードが走ることを意味しない」と言っているのは、まさにこの形である。

## 決定

**CLI のコマンドを `check` の 1 つにする。** 全部の検査をそこが走らせる。有限値の注釈、1 つの値集合を複数の概念が宣言している状態、同じ綴りの本体、ワークフロー定義の 6 種類。

**1 件でも見つかれば非ゼロで終わる。** 報告だけ出してゼロで終わる検査を残さない。

**`equivalent-concepts` と `duplicated-bodies` の報告文を書き直した。** ゲートの失敗になる以上、`enforcement.md` の「ガードの報告に、破られた不変条件と直す方向の両方を含める」が掛かる。どちらも違反の事実だけを並べていて、直す方向を持っていなかった。

## 影響

**`guard` の 3 行が 1 行になった。** `vp exec dont-review-it check` だけになる。

**導入時点で新しい違反は出ていない。** 4 つの検査はいずれも mst に対して 0 件だったので、終了コードを厳しくしても緑のままである。緩い側から厳しい側へ移すときに既存の違反を抱えていない。

**呼び分けの口が無くなった。** 「重複だけ見たい」のような部分実行はできない。部分実行が要る場面は、検査を書いている最中にその検査だけ動かしたいときで、それはテストの側でできる。

**後方互換は取っていない。** 消したサブコマンド名は `AGENTS.md` の規約どおり残していない。
