# 0034. 違反の判定と直し方の選択を分ける

- ステータス: Accepted
- 日付: 2026-08-11

## 文脈

[強制の機構](../guidelines/enforcement.md) は、ガードの報告に破られた不変条件と直す方向の両方を求め、安全で決定的な直し方が 1 つだけなら自動修正を用意し、有効な直し方が複数なら自動修正を禁じている。自動修正できない部分も失敗するガードに残す。

一方、`@mst/dont-review-it` の規約は、直し方が一意に決まる問いだけをルールにし、直し方が複数ある検査結果を warning として終了コードに数えないことにしていた。[0028](0028-keep-the-catalog-for-shared-versions-only.md) はこの境界に従い、catalog と manifest のバージョンが食い違う場合と、複数の manifest が同じ依存に異なるバージョンを書く場合を warning にした。

この区分では、同じ不変条件に対する違反でも、選ぶべき値が既に揃っていれば失敗し、値を人が選ぶ必要があれば成功する。ガードが判定できているのは「バージョン宣言が 1 か所に集約されていない」という違反状態であり、どのバージョンを採るかではない。修正の選択肢が複数あることを理由に成功へ読み替えると、検出した違反をガードが通す。

## 決定

**違反状態を決定的に判定できるかと、直し方が一意に決まるかを分ける。** 違反状態を機械が決定的に判定でき、破られた不変条件と修正の方向を報告できるなら、直し方が複数あっても失敗として扱う。

**自動修正の有無だけを直し方の数で決める。** 安全で決定的な直し方が 1 つだけなら自動修正を持たせる。有効な直し方が複数ある場合は自動修正を持たせず、選択後に満たすべき状態を報告する。

**`dont-review-it check` から warning の経路を外す。** 検査が問題として報告する項目はすべて終了コードに数える。情報を表示するだけで成功する経路は持たない。

**依存バージョンの食い違いを problem にする。** catalog と manifest が異なるバージョンを持つ場合は、意図するバージョンを選び、catalog に残し、manifest を `catalog:` 参照へ変えるよう報告する。catalog の外で複数の manifest が異なるバージョンを持つ場合は、意図するバージョンを選び、catalog に置き、すべての manifest をその参照へ変えるよう報告する。どのバージョンを選ぶかは自動修正しない。

この決定は、[0028](0028-keep-the-catalog-for-shared-versions-only.md) がバージョンの食い違いを warning にした決定と、warning を持つことを帰結とした部分を置き換える。catalog の対象、単一使用 entry、overrides、未使用 entry、catalog に置けない protocol の境界は変えない。

## 影響

- `DependencyCatalogFindings` は problem の配列だけを返し、warning の配列を持たない
- `dont-review-it check` は依存バージョンの食い違いを出力した場合も非ゼロで終了する
- メッセージは採用するバージョンを決め打ちせず、選んだ後に catalog へ集約する方向を示す
- 自動修正を持たない lint ルールや検証コマンドも、違反状態を決定的に判定できる限り error のまま保つ

## 検討して採らなかった案

**直し方が一意でない事象を warning のまま残す。** 値を選ぶ作業は人に残せるが、違反状態も成功として通過する。ガードが既に見つけた不変条件違反を main に入れられるため採らない。

**warning を出しつつ終了コードには数える。** 表示上の warning と実行結果の失敗が食い違い、重大度から終了状態を予測できなくなる。失敗として扱う項目は problem として報告する。
