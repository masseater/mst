# 0035. 終了コードには成否だけを載せ、理由は標準エラーに書く

- ステータス: Accepted
- 日付: 2026-08-12

## 文脈

`throttle` と `spool` はフックとスクリプトの中で使われる。呼び出し側が分岐に使えるのは終了コードだけであり、細かく区分しても分岐には使われない。一方で、フックが落ちたときに「検査に落ちた」のか「フックの書き方を間違えた」のかが判別できないと、直す場所を探す時間が失われる。

## 決定

**throttle は 3 区分。** 成功 0 ／ 包んだコマンドの失敗 1 ／ throttle 自身の使い方の誤り 2。非ゼロ終了・シグナル終了・起動失敗・打ち切りは 1 に潰し、理由の別は標準エラーの文言で伝える。競合以外の環境障害と待機予算の満了も 1 に載せる。誤りの 2 だけは混ぜない。値は `@mst/repository-checks` の EXIT 語彙（0/1/2）と揃えた。

**spool は子のコードを透過する。** 子が選んだ値は 0 も非 0 も加工しない。子がシグナルで死んだときは慣行どおり 128+シグナル番号、起動できなかったときは 127、記録に失敗したときは 1、使い方の誤りは 2。子の値空間と重なる衝突は許容し、区別はチャネルと文言に委ねる。記録に失敗した実行は子が成功していても失敗として返す。存在しない記録を指すポインタを渡さないためで、この経路では子自身の結末は終了コードから復元できない。

**告知と進捗は標準エラーへ。** throttle の獲得開始・待機の進捗・コマンド行の告知、spool の失敗理由は標準エラーに書く。標準出力は結果のみという配置規約（`docs/guidelines/placement-and-tools.md`）に従い、入口の出力を変数に取り込む呼び出し元が現れても進捗が混ざらないようにする。spool の要約だけは、ラッパーが仕事を果たせた場合（子が決着し、退避の経路では記録できた場合）に標準出力へ書く。要約は結果だからである。

**退避先は作業ツリーの `.spool/`、保持方針は持たない。** 位置は package.json を目印にした上方探索で決まるので、ワークスペースの中で走らせた実行の記録はそのワークスペースの直下に置かれる。`.gitignore` の `.spool/` が全階層を版管理から外す。作業ツリーを捨てれば記録も一緒に消えるので、削除の主体を別に立てない。それまでは実行のたびに 1 ファイル増え続ける。この性質はパッケージの `AGENTS.md` と SKILL に明記した。CI ではジョブログ自体が耐久的な受け皿なので、`CI` 環境変数を信号に素通しへ切り替え、二重の記録を作らない。

## 影響

- 終了コードだけを見る呼び出し元には「spool 自身が失敗した」と「子が同じ値で終了した」の区別が届かない。区別が要る呼び出し元は標準エラーの文言を見る。
- `.spool/` は増える一方である。長寿命の作業ツリーでディスクが気になったら、掃除の機構はそのとき初めて設計する。
