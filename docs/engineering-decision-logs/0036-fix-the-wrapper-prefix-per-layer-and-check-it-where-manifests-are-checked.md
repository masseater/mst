# 0036. ラッパーの前置きを層ごとに固定し、マニフェストを検査する場所で検査する

- ステータス: Accepted
- 日付: 2026-08-12

## 文脈

`throttle` と `spool` は使われなければ効かない。包み忘れは包み忘れた当人の実行を失敗させず、代償は別の場所（並走する他の作業ツリー、出力を読む側の context window）に現れるため、案内だけの規律は必ず崩れる。実行を横取りする形は呼び出し元ごとに用意が要るので、検査の対象は実行ではなく定義に置く。入口の定義は有限で、リポジトリの中にあり、すべての呼び出し元が共通に通る。

このリポジトリの入口の定義は package.json の scripts である。マニフェストを検査して非ゼロで止める走行は `dont-review-it check` に集約済みで（[EDR 0026](0026-give-the-checks-one-entry-that-fails.md)）、合成の検査もそこに載せる。

## 決定

**層は 2 つ、前置きは層ごとに固定する。** 上位はルートの `guard`（CI とフックが呼ぶ唯一のゲート）で、`throttle --timeout 1800 -- spool -- ` を必須の前置きとする。下位は各ワークスペースの `test`・`build`・`check` で、存在するなら `spool -- ` で始まることを要求し、上限ラッパーは含めない。上限を上位だけに置くのは、throttle が入れ子で意味を失う（内側が独立の競合者としてスロットをもう 1 つ消費する）ためで、層ごとの固定文字列がこの約束を機械の側に載せる。

**`guard` は 2 段にする。** `guard` は `throttle ... -- spool -- vp run guard:all` の 1 コマンドとし、従来の検査の列は `guard:all` が持つ。`&&` で連ねた列に前置きを付けても、シェルの解釈では最初のコマンドしか包まれないからである。スクリプトは 1 コマンド呼び出しに保つという enforcement の方針とも揃う。

**検査は 5 種を区別して報告し、安全で決定的な自動修正だけを `check --write` が持つ。** 要求された名前が無い／マニフェストに scripts が無い／名前はあるが文字列でない／文字列だが command body が無い／文字列の本体はあるが前置きで始まらない、を区別し、先頭不一致の報告には要求と実際の両方を含める。名前、scripts、または文字列の本体が無い場合は、入口が呼ぶべき本体を機械が決められないため報告に留める。既存の文字列の本体がある先頭不一致だけは、自層の要素を取り除いてから前置きを付け直す。冪等であり、自層に属さないラッパーが先頭にある値も機械で直さず報告に留める。直し方が一意でなければ自動修正を用意しないという方針（`docs/guidelines/enforcement.md`）の適用である。

**検査が見るのは値の前置きと、前置きの後ろに空でない command body があることだけである。** 定義の外での起動、command body の振る舞い、前置きの後ろに足された包まれていないコマンドは視野の外にある。広げるには値の全体を読む検査が要り、正当な記述と違反を区別する基準を作れていないので、境界として記録する。

## 影響

- 新しいワークスペースを足すと、`test`・`build`・`check` を書いた時点でこの検査の対象になる。既存の本体から修正後の値が一意に決まる場合だけ、`check --write` が前置きを機械で埋める。
- 固定文字列を変えると既存の全定義が一斉に不一致になり、自動修正が一斉に書き換える。冪等性のテストがこの瞬間の二重前置を防ぐ。
- `guard` の出力は `.spool/` の記録ファイルへ入り、端末には待機の告知と固定行数の要約だけが出る。全文が要るときは要約が指すファイルを開く。
