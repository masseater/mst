# 0041. 検査の走査証跡を標準エラーに書き、読み手は実行時文脈から判別する

- ステータス: Accepted
- 日付: 2026-08-12

## 文脈

`dont-review-it check` は違反を 1 件も見つけなければ何も書かずに 0 で終わる。空のディレクトリを指して走らせても、出力と終了コードは同じである。9 つの観点がすべて対象を 1 つも開けずに空振りした実行と、すべて開いた上で違反が無かった実行が、外から区別できない。

このパッケージは `no-unchecked-authored-path` として「何も開かない検査は、何も見つからなかった検査として通るのではなく報告される」を他所に強制している。CLI 自身がその外に立っていた。

## 決定

**観点ごとに、開いた対象の単位と数を残す。** 検査の結果を「問題の一覧」から「観点ごとの結果の一覧」へ変えた。観点は自分が何をいくつ開いたかを持ち、対象を持てなかった場合はその理由を持つ。理由を持つ観点は、対象を開いて違反が無かった観点と別の表示になる。両者が区別できないことがこの決定の起点なので、書式の都合でここを潰さない。

**証跡は標準エラーへ書く。** 標準出力は結果のみという配置規約（[EDR 0035](0035-let-exit-codes-carry-the-outcome-and-stderr-carry-the-reason.md)）に従う。走査の事実は結果ではない。検査の出力を変数に取り込む呼び出し元が現れても、証跡が結果に混ざらない。

**読み手は実行時文脈から判別し、フラグを作らない。** 人間が読む形と AI が読む形は別物である。人間向けは状態を記号で示し、桁を揃え、末尾に要約を置く。AI 向けは記号も色も整列も要約も持たず、1 行 1 観点の平坦な形にする。どちらを出すかは `--verbose` のようなモードフラグではなく実行時文脈から導く。呼び出し側が保守するモードフラグで挙動を分けることは CLI の規範が禁じており、読み手の判別も同じ扱いにした。

**判別は `std-env` に委ねる。** `isAgent` が Claude Code・Cursor・Codex・Gemini CLI などを環境変数から判定する。自前で環境変数の一覧を持たない。このパッケージは既に依存グラフの中にあり、色の可否も同じ入口から取れる。候補として `@vercel/detect-agent` があったが、検出しか行わず、判定が非同期で、依存として新規に増える。

**対象ゼロは失敗にしない。** 依存宣言の検査がワークスペース定義の無いリポジトリで何も検査しないことは仕様として確定している。空振りを失敗に変えると、この約束が変わる。空振りは証跡の上で「開かなかった」と読めれば足りる。

## 影響

- 検査の入口の戻り値が変わった。観点ごとの結果を主とし、問題と警告はそこから導出する。`@mst/lint-rule-authoring` の索引照合も同じ形に揃えた。
- 値の正典と重複本体の 2 観点は、対象の数を検査そのものからではなく集約層のファイル走査から取っている。証跡が示すのはこの 2 観点だけ「検査が開いた数」ではなく「集約層が同じ条件で数えた数」であり、走査の条件が食い違えば数も食い違う。
- 証跡は常に出る。抑止する手段を持たないので、出力を捨てたい呼び出し元は標準エラーを捨てる。
- 読み手の判別が環境変数に依存するため、同じリポジトリに対する実行でも人間と AI で標準エラーの内容が変わる。標準出力は変わらない。
