# 0005. コメント構文に残すのは機械が読む宣言だけにする

- ステータス: Accepted
- 日付: 2026-08-10

## 文脈

`@mst/dont-review-it` に最初に入れたコメント関連の 2 本は、同じ線引きの表と裏になっている。

- `no-explanatory-comment--delete-or-move-to-commit-message` — コメント全体を見て、通す対象を lint 抑制ディレクティブ・コンパイラディレクティブ・JSDoc ブロックの 3 つに絞る
- `no-detached-rationale--comment-at-explained-line` — JSDoc ブロックの中身を見て、最初のタグより前の説明散文を落とす

JSDoc の中身を前者が見ないのは、二重報告を避けるための役割分担である。

移植の参照実装は、これに加えて JSDoc 内の非英語表記も拒否していた。

## 決定

非英語表記の検査は入れない。

mst で英語を強制するかは方針判断であり、まだ決まっていない。コメント自体を全面禁止にした結果、コメント構文に残せるのは JSDoc の `@tag` の中身だけになり、それを書く場面がまだ無い。公開 API に JSDoc を書く段で決める。

## 影響

人間向けの散文をコメント構文に置ける場所は、JSDoc のタグ配下だけになった。それ以外の経緯はコミットメッセージの本文に、コードレベルを超える意思決定は `docs/engineering-decision-logs/` に置く。

そのタグ配下に書く言語は検査されない。書く場面が現れたときに、そのまま書けてしまう状態で判断することになる。判断を先送りしたこと自体はこの記録で追える。

## 検討して採らなかった案

**参照実装のまま非英語表記の検査を入れる。** 検査は動くが、根拠になる方針が無い状態で強制だけが先に効く。書く場面がまだ無いため、方針が決まる前に効かせても当たり方を確かめられない。
