# 0051. 何も収集しなかった実行を落とす

- ステータス: Accepted
- 日付: 2026-08-13

## 文脈

Vitest は `passWithNoTests` を持つ。`true` にすると、テストファイルを 1 つも収集しなかった実行が成功として終わる。既定は `false` で、自動的に `true` へ倒れるのは `vitest related` と `--changed` を使ったときだけである（`vitest@4.1.10` の `cac` と `coverage` の解決で確認した）。

この選択が入る経路は「実行が落ちたから止めた」である。空の実行が落ちるのは、テストを書いていないか、収集の設定が壊れてテストが対象から外れたかのどちらかで、直す対象はどちらも設定ではない。1 行の宣言でその赤が消え、消えた赤が何だったのかは後から読めない。

ゲートが読むのは終了コードだけなので、テストが 1 件も走らなかった実行と、テストが全部通った実行は、この宣言の下では区別されない。[EDR 0015](0015-decide-what-a-failure-may-become.md) が扱った「読めないディレクトリを空として扱い、配下がすべて対象から消えても緑だった」事象と同じ形が、テストの収集の側で起きうる。

[EDR 0015 の判断を受けた `no-lenient-coverage-threshold--demand-full-coverage`](../../packages/dont-review-it/docs/lint/no-lenient-coverage-threshold--demand-full-coverage.md) はテスト設定の下限を要求しているが、見ているのはカバレッジの数字だけで、実行が空でよいかは見ていない。カバレッジの下限はテストが 1 件でも走った実行にしか効かず、0 件の実行はそもそも計測の対象を持たない。

## 決定

**空の実行を成功として終わらせる宣言を禁じる。** `no-vacuous-test-run--let-the-empty-run-fail` が、テストランナーの設定ファイルの `test.passWithNoTests` を読み、`true` を報告する。直し方は「削除する」に一意に決まるので error にする。

**値をこのファイルだけで読めない形も報告する。** 変数参照・短縮記法・実行時に評価される式・真偽値でないリテラルが該当する。空の実行がどちらに転ぶかを設定ファイルから読めない状態は、`true` と同じだけ判断を外へ逃がす。`no-lenient-coverage-threshold--demand-full-coverage` が下限について取っている扱いと同じにする。

**`false` は通す。** 既定と同じ宣言だが、空の実行を失敗として扱うことを書き手が明示した形であり、要求する状態と一致する。プロパティが無い場合と区別しない。

**カバレッジのルールとは別のルールにする。** 見ている不変条件が違う。カバレッジの下限は「走った実行がどこまで覆ったか」を、こちらは「実行が走ったか」を要求する。1 本にまとめると、片方だけを緩めたいときにもう片方まで一緒に外れる。ルール名が直し方を述べる形も保てなくなる。

**出荷する preset に載せる。** 空の実行を成功として数えてよいリポジトリは無く、採用者の方針で分かれる問いではない。`no-version-range--pin-the-exact-version` をルート設定だけに置いた[EDR 0041](0041-let-the-declaration-decide-the-release.md) の判断とはここで分かれる。

**オプションを持たない。** 緩める軸が存在しない。テストを持つべきでないワークスペースがあるなら、外すのはテストの実行そのものであって、空の実行の扱いではない。

**読めない設定は報告しない。** default export が無い、default export が変数を指している、`test` がオブジェクトリテラルでない、のいずれも黙って通す。同じファイルに対して `no-lenient-coverage-threshold--demand-full-coverage` が既に報告しており、1 つの原因に対して直し方が 2 通り並ぶことを避ける。

**コマンドライン引数は見ない。** `--passWithNoTests` は起動の記述であって設定ファイルの宣言ではなく、lint が読める材料に入っていない。検出できないことは許していることを意味しないので、ルールの文書で禁じる回避策として名指しする。

## 影響

**テストを持たないワークスペースが、緑のまま増えることがなくなる。** 実行が空になった時点で落ちるので、テストを書くか、そのワークスペースでテストを実行しないと決めるかのどちらかを、その場で選ぶことになる。

**収集の設定が壊れたことが次の実行で分かる。** テストが実際に存在するワークスペースでも、収集の範囲を変えれば 0 件になりうる。落ちたテストは誰かが直すが、走らなくなったテストは誰も気付かない、という差がここで消える。

**テスト設定として認識するファイル名の集合が 1 か所に寄った。** `no-lenient-coverage-threshold--demand-full-coverage` が持っていた判定を共有の読み手へ移し、両方のルールが同じ集合を見る。片方だけが `vitest.config.ts` を見落とす状態を作れない。
