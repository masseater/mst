# 0037. PR 自動応答ランタイムは不変条件から導く

- ステータス: Accepted
- 日付: 2026-08-12

## 文脈

GitHub の PR に対して AI エージェントを走らせる常駐ランタイムを、このリポジトリの資産として持ちたかった。同種の仕組みは業務のリポジトリ基盤整備として既に存在していたが、成果物そのものの権利はそちらにある。表現をなぞった実装は、書き直した体裁でも複製として扱われる。

一方で、この領域の難しさは表現ではなく不変条件の側にある。「PR の最新コミットに付くステータスが、常にその PR の現在の入力に対する結果を表す」「待っても直らない失敗では止まり、待てば直る失敗では再試行し続ける」「再起動を跨いでも取りこぼしと二重実行を起こさない」——これらは、公開されている技術と一般的な知識だけを入力にしても書ける。書けないのは、特定の環境で観測された定数や、雇用先の識別子を含む断片である。

この分離を、作業手順として強制できる形にする必要があった。

## 決定

**移植を 2 段階に分け、段の間で参照を切る。** 第 1 段では移植元を読み、守りたい不変条件と検出したい違反の性質だけを自然言語で書き出す。第 2 段では書き出しだけを入力に、実装とテストと文書を書く。実装中に移植元を開き直さない。出来上がった形が不変条件から導かれたことを、後から手順で説明できる。

**`mst` のディレクトリで立てたセッションからは、移植元が構造的に見えない状態を保つ。** 追加作業ディレクトリとして加えない。参照を切る規律を、記憶ではなく環境で支える。

**判定に迷う断片は持ち込まない。** 基準は「移植元を見ずに、公開されている技術と一般的な知識だけでこれを書けるか」。書けないものは、汎用に見えても移植元固有の情報が混ざっている。

## この決定が生んだ差分

書き出しの段階で、いくつかの値と構成が「不変条件ではなく観測」だと分かった。それらは意図だけを残して数字を選び直すか、採用自体を落とした。

- worktree の保持期間と回収間隔、エンジン出力のバッファ上限は、移植元の運用実績から来ている可能性を否定できなかった。「アクティブなブランチを守りつつディスクを回収する」という意図だけを残し、値はこのリポジトリの設定既定として決め直した
- 移植元がフック運用の設計として持っていた worktree セットアップの 2 段プロトコルは採用しなかった。「注入されたセットアップコマンドを worktree で実行し、失敗を伝播する」という汎用部分だけを仕様にした
- 認証失効の検知に使う文言は、対象 CLI が公開挙動として出すエラーテキストであり汎用と判断した。ただし CLI のバージョンで変わる観測値でもあるため、照合はパターンの部分一致に留め、一致した文言をエラー自身に持たせて後から追えるようにした

社名・サービス名・チケット接頭辞・ホスト名・クラウドリソース名は、パッケージ全体を検索して 1 件も持ち込んでいないことを確認した。

## 帰結

同じ不変条件を満たす実装が 2 つ存在することになるが、片方は不変条件から導かれた別の成果物であり、この形が資産化の手段そのものである。

移植元は削除される予定だが、削除は持ち出しの事実を消さない。この決定は削除の予定を根拠にしていない。
