# 0029. 生成された索引の字面は整形器に持たせる

- ステータス: Accepted
- 日付: 2026-08-11

## 文脈

各ワークスペースの `docs/lint/index.md` は、マニフェストの `lintRules` が宣言する置き場からルールを発見して生成する表を、マーカーで区切った領域に持つ。生成は `lint-rule-authoring check --write` が行い、鮮度の検査は [0026](0026-give-the-checks-one-entry-that-fails.md) の入口である `dont-review-it check` が行う。

oxfmt は markdown の表を列ごとにパディングして揃える。幅の計算は文字の表示幅に基づき、日本語や絵文字は 1 文字を幅 2 として数える。生成器が書いた素の表は `vp check --fix` で必ず書き換わる。

このとき鮮度の検査がバイト一致を要求すると、整形器が畳んだ字面を検査が「古い」と報告し、書き込みと整形が互いの出力を差し戻し合って `guard:fix` が収束しなくなる。逆に oxfmt の幅計算を生成器へ複製すると、二重に持った計算が oxfmt の更新のたびにずれる。

## 決定

**生成器は素の表を書き、字面は oxfmt に持たせる。** 内容の権威は生成器、字面の権威は整形器、という分担に固定する。

鮮度の比較は両辺を同じ関数で正規化してから行う。行ごとに前後の空白を落とし、空白の連続を 1 つに畳み、3 連以上のハイフンを 3 連に畳み、空行を除く。整形器が変えてよいのはこの正規化で消える差分だけなので、内容の変化だけが「古い」として残る。

`guard:fix` は `lint-rule-authoring check --write` を `vp check --fix` より前に走らせる。生成直後の素の表を、同じ実行の中で整形器が畳む。

## 影響

生成器と整形器が同じファイルを書いても収束する。`guard:fix` を 1 回流せば、索引は内容も字面も定まった状態になる。

空白だけの書き換えは検査を素通りする。これは分担の帰結であり、字面を守りたいなら oxfmt の側で守る。

比較の正規化を弱めてはならない。ハイフンの畳み込みを外すと、整形器が揃えた区切り行がそのまま「古い」に化ける。
