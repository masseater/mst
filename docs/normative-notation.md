# 規範の書き方

このリポジトリの `AGENTS.md` は、人間と AI の両方が読む。読み手が「その規範が今の自分に効くか」を機械的に判定できる形に揃える。`@mst/agentic-documents` の検査がこの記法を強制する。

## 記法

規範は箇条書きの項目として書く。1 項目が 1 つの規範を表す。

条件を持つ規範は `IF: <条件>; THEN` で始める。条件が成立したときの行動が 1 つなら同じ行に続け、複数なら入れ子の項目として並べる。条件を持たない規範は判断キーワードから始める。

判断キーワードは `MUST` `PROHIBIT` `SHOULD` `SHOULD NOT` `MAY` の 5 つで、直後にコロンを置く。コロンが判断であることの印であり、コロンを伴わない綴りは記法の説明とみなされる。

禁止は `PROHIBIT` と書く。`MUST NOT` は使わない。行頭の 1 語で義務と禁止を判別できるようにするためで、`MUST NOT` は 2 語目まで読まないと意味が反転したことが分からない。

行動は 1 文で言い切る。理由や補足は、その項目の下の入れ子に置く。行動の行に理由を続けると、行動の終わりがどこかを機械が決められず、読み手にとっては理由が適用条件のように読める。

## 置かないもの

規範を表の行に落とさない。表の行には判断キーワードを置く場所も、入れ子も、理由の置き場もない。規範ではない一覧を表で示したい場合は、その一覧を `AGENTS.md` の外の文書へ移す。

同じ階層で同じ条件を繰り返さない。条件を 1 度だけ書き、行動をその下に並べる。

番号付きの手順は 1 から始まる連続した整数で書く。0 から始める、小数を割り込ませる、番号を飛ばす、のいずれもしない。

道具や依存の版を散文に直書きしない。版を決めているファイルの名前を書き、値はそちらを読ませる。

良い例と悪い例のコードを対で置かない。その差が機械で判別できるなら検査を書き、判別できないなら何を見て判断するのかを条件と行動として書く。

## 検査

`vp run docs` で検査する。生成される部分は `vp run docs:write` で更新される。

検査が見る範囲、判断キーワードの綴り、文末の記号などは `packages/agentic-documents/src/config.ts` の既定値が決めている。
