# コードの書き方

このリポジトリのコードは、ここから配る lint ルールと検証コマンドが最初に当たる対象である。守りたいのは、検査が緑であることと、検査された対象が実際にそこにあったことがずれない状態で、コードの書き方はその一点に効く。

ずれ方はどれも形が同じで、崩れた瞬間には何も起きない。[0015. 失敗が値に化けてよい範囲を決める](../engineering-decision-logs/0015-decide-what-a-failure-may-become.md) は、読めないディレクトリが空のディレクトリとして扱われ、その配下が走査から丸ごと消え、それでも `vp run ready` が緑のままだった状態を記録している。定義が二つに割れているとき、確かめずに型だけを強めたとき、失敗を代替値に潰したときにも、行き着く先は同じである。

テストの書き方は [テスト](tests.md)、機微な値の扱いは [秘密と権限](secrets-and-permissions.md)、これらをどの機構で強制するかは [強制の機構](enforcement.md)、レビューで見つかった違反の扱いは [レビューの指摘](review-findings.md) が持つ。ここに書かれた判断の一般形は [中核原則](principles.md) にある。

## 外部 I/O とその境界

この文書で外部 I/O と呼ぶのは、値がこのリポジトリのロジックの外側で決まる経路である。他の文書がこの語を使うときは、この定義を指す。このリポジトリにあるのは、CLI に渡された引数と標準出力、計測の有効化と送り先を決める環境変数、走査とキャッシュのファイル読み書き、型チェッカの子プロセス、計測値の送信である。これに当たらない依存は、プロセス内の決定的な振る舞いとして扱う。

- IF: ロジックが外部 I/O に触れる; THEN
  - MUST: このリポジトリが所有する注入境界を経由する
  - PROHIBIT: ロジックの中から外部 I/O を直接呼ぶ
- IF: 注入境界を足す; THEN
  - MUST: それが外部 I/O の位置にあるか、今それを呼んでいるテストではない経路があるかを先に示す
  - PROHIBIT: どちらも示せない注入境界を足す
    - このリポジトリの注入境界は、ルールが読み取りの実装を受け取る位置と、検証コマンドが走査の根を受け取る位置で、実物を渡しているのは `plugin.ts` と CLI である
- IF: 外部 I/O の位置に注入境界を置いた; THEN SHOULD: 向こう側を差し替えたときに、こちら側の分岐を全部通せる大きさに保つ
  - 判断は、差し替えるものの種類を増やさずに分岐を全部通せるかで見る
- IF: 存在が任意のパスを読む; THEN
  - MUST: 読む前に不在を判定する
  - PROHIBIT: 読み取りの失敗をすべて不在として扱う
    - 不在と、あるが読めないことの分け方は [0015. 失敗が値に化けてよい範囲を決める](../engineering-decision-logs/0015-decide-what-a-failure-may-become.md) が決めている
- IF: 存在が任意のディレクトリの下に書く; THEN
  - MUST: 書く前にディレクトリを用意する
  - PROHIBIT: 書き込みの失敗を存在確認の代わりに使う

## 外から入った値を内側の型にする

静的な型は実行時に消えるので、外から入ってきた値について型が言っていることは、確かめた誰かがいて初めて事実になる。

- IF: 外から来た値を内側の型として扱いたい; THEN
  - MUST: その型へ移す位置を、値がこのリポジトリへ入ってくる境界に置く
  - PROHIBIT: 使う場所ごとに形を確かめる
- IF: 境界で形が合わなかった; THEN MUST: 内側の型を作らずに失敗として扱う
- IF: 一つの判定を二つの概念に使いたくなった; THEN
  - MUST: 概念ごとに別の判定を定義する
  - PROHIBIT: いま構造が一致していることを理由に共有する
    - [ワークスペース](../workspaces.md)を生成する走査は、一覧に載る成果と載れない理由を、どちらもディレクトリ名と一つの文字列という同じ構造で持ちながら、別の概念として別々に宣言している
- MUST: 判定を通った形を表す静的型を、その判定の定義から導出する
- MUST: フィールドが人にとって何を意味するかを、同じ判定の定義に持たせる
- IF: 判定が受け入れる形を緩める; THEN
  - MUST: 満たすべき形が文脈ごとに変わるなら、どの文脈かを決める値を先に読み、その文脈の判定を選ぶ
  - MUST: 省略可能にするフィールドについて、実際に欠ける場面を挙げる
  - PROHIBIT: 全文脈のフィールドを省略可能にして一つの判定へ畳む
  - PROHIBIT: 欠ける場面を挙げられないまま省略可能にする
- IF: 判定を書く手段を選ぶ; THEN
  - MUST: このリポジトリで一つに保つ
  - PROHIBIT: 選んだ手段の外側で、条件を並べただけの検査を書く

## 型が言えることと、確かめて初めて言えること

- MUST: その場で使える中で最も精密で健全な型を保つ
- IF: 不正な状態を型のうえで表現不能にできる; THEN
  - MUST: そこで制約を表現する
  - PROHIBIT: 呼び出し側の規律に頼る
- MUST: 関数の引数と戻り値の契約は、関数シグネチャを唯一の出所とする
- IF: 同じ型が関数の外でも要る; THEN
  - MUST: 関数シグネチャから導出する
  - PROHIBIT: 構造だけ同じ型を別に宣言して並行させる
    - 型に名前を付けてよい条件は [0019. 型に名前を付けるのは 2 箇所が合意するときだけにする](../engineering-decision-logs/0019-name-a-type-only-where-two-places-agree.md) が決めている
- IF: ある値を、その場の型検査が導けない型として扱わせる; THEN
  - MUST: その値が主張どおりであることを実際に確かめる検査を、同じ境界に置く
  - MUST: 検査を通った値だけを主張の対象にする
  - PROHIBIT: 検査を伴わない主張で、型検査器が出すはずだった拒否を消す
    - 主張の綴りは問わない。アサーションも、型述語を名乗る関数も、表明する関数も、中身が値を見ていなければ同じことをしている
- IF: 依存を実行時のモジュールとして取り込む; THEN
  - MUST: そのパッケージの実行時のモジュール形式が消費側と噛み合うことを確かめる
  - PROHIBIT: 型解決が通ったことを、実行時に読めることの証拠として扱う

## 既にある定義の上に書く

同じことを言う場所が二つに割れる経路は、書き足す位置を選ぶ時点にある。既にある定義を探さずに書けば所有者が二つになり、欠陥の原因から離れた位置で塞げば回避策が定義として残る。

- IF: ある振る舞い・ルール・値に既に所有者がいる; THEN
  - MUST: その所有者を再利用するか拡張する
  - PROHIBIT: 等価なものをその場に作る
    - 機械が落とせる重複の範囲は [0013. 重複の検出線を決定可能性で引く](../engineering-decision-logs/0013-draw-the-duplication-line-at-decidability.md) が決めている
- IF: 欠陥を直す; THEN
  - MUST: その欠陥を所有している境界で原因を直す
  - PROHIBIT: 原因の外側に置いた分岐や迂回の経路を、修正として残す
- IF: 同じ規約を複数のもっともらしい書き方で表現できる状態を見つけた; THEN
  - MUST: 型・境界・自動検査のいずれかを締めて、通る書き方が一つになるまで絞る
  - PROHIBIT: 規約を文書に書いたことで対処を終える

## 失敗を型で表す

何を送出し、何を戻り値にするかは、呼び出し側がその失敗を予期できるかどうかで決まる。どこまでを値にしてよいかは [0015. 失敗が値に化けてよい範囲を決める](../engineering-decision-logs/0015-decide-what-a-failure-may-become.md) が決めている。

- IF: 失敗しうる関数を書く; THEN
  - MUST: 予期した失敗と予期しない失敗を、呼び出し側がコードから区別できる形にする
  - PROHIBIT: 同じリポジトリの中に失敗の伝わり方を二通り持つ
    - 予期しない失敗はどのみち送出で上へ伝わるので、予期した失敗も送出に寄せれば経路は一本で済む
- IF: 予期した失敗や、外へ出す報告を定義する; THEN
  - MUST: その同一性を、安定した識別子が持つ形にする
    - 鍵になれるのは、ルール名・報告の識別子・実行環境が失敗に付ける `code` のように、言い回しでは変わらないものだけである
  - PROHIBIT: 同一性をメッセージ本文の一致で判定する
- IF: 下位の層や依存パッケージから来た失敗を包む; THEN
  - MUST: 元の失敗を `cause` として保持する
  - PROHIBIT: 文言だけを取り出して元の失敗を捨てる
    - 文脈を足すのはよいが、足すのであって置き換えるのではない

## 失敗を消さない

失敗が消える書き方は三つある。受け取らずに捨てる、書き出してから続ける、代替値に置き換える。どれも結果は同じで、失敗はその失敗自身の不在を表す値に化ける。

- IF: 失敗を捕まえた; THEN
  - MUST: 捕まえたものに名前を付けて受け取る
  - PROHIBIT: 受け取らずに捨てる
- IF: 捕まえた失敗を出力先へ書き出す; THEN
  - MUST: 書き出したうえで、止めるか、失敗したと分かる値を戻す
  - PROHIBIT: 書き出してからそのまま続きへ進む
- IF: 失敗を握り潰してよいかを判断する; THEN MUST: [0015. 失敗が値に化けてよい範囲を決める](../engineering-decision-logs/0015-decide-what-a-failure-may-become.md) が置いた条件に照らして決める
- PROHIBIT: 失敗を別の綴りへ移したり、包む関数を挟んだりして、握り潰しの検出から外す

三つ目の代替値は、失敗を一見成功した実行に変える操作である。許す線は握り潰しと同じところに引く。検査される対象の集合と、報告される箇所の集合が動かないことである。

- IF: 失敗したときに代替値で続行したい; THEN
  - MUST: その置換を許す明示的な仕様があることを確かめる
  - MUST: その置換が、検査される対象の集合と報告される箇所の集合のどちらも変えないことを示す
  - MUST: 置換後の値を受け取る側が、その値で成立することを確かめる
  - MUST: 置換が起きたことを、実行の外から成功と区別できる形で残す
  - PROHIBIT: 四つのうち示せていないものがあるまま続行する

## 実行時に残る記録

原因まで辿れない失敗は、報告としては起きなかったのとほとんど変わらない。記録は、何を残すかと、どの経路へ流すかの二つで決まる。

- IF: 捕まえた失敗を記録する; THEN
  - MUST: 失敗そのものと、`cause` で繋がった連なりを残す
  - PROHIBIT: 文言だけを写して元を落とす
- IF: 記録を出す発生源を足す; THEN
  - MUST: 発生源の種別ごとに、流す経路を一つ決める
    - このリポジトリで記録が生まれるのは、lint ルールの実行、検証コマンド、CI の各ステップ、開発サーバーである
  - PROHIBIT: 経路を決めないまま出力先を増やす
- PROHIBIT: 一つの発生源の記録を、複数の経路へ重複して流す
- IF: 一つの発生源の記録が既に複数の経路へ流れている; THEN MUST: 経路を一本に寄せる
- PROHIBIT: 記録を中継するためだけに存在する中間の処理を残す
  - 呼び先をそのまま呼ぶだけの中継は [no-identity-wrapper--call-the-target-directly](../../packages/dont-review-it/docs/lint/no-identity-wrapper--call-the-target-directly.md) が落とす
- IF: 実行時の計測を足す; THEN MUST: 何をどこへ送るかを [0021. 自作 lint ルールの実行時間を自分で測り、送り先は使う側に決めさせる](../engineering-decision-logs/0021-measure-our-own-lint-rules-and-let-the-user-choose-the-sink.md) の決定に従って決める
- IF: 出してよいと判断した内容が、記録の出力先の容量に収まらない; THEN
  - MUST: 出力先を分けるか、構造化した欄へ移す
  - PROHIBIT: 収まる分量まで削って残りを捨てる
    - どの削り方を選んでも、削ったこと自体は残った記録に現れない
- IF: どうしても内容を記録の本文から落とさざるを得ない; THEN
  - MUST: 落とした事実を記録に残す
  - MUST: 在り処として指すのを、その記録の読み手に開示が許されている場所だけにする

## 名前が伝えること

引数の名前と型は、呼び出す前に読まれる唯一の情報である。

- IF: 受け付ける形を呼び出し側へ伝える位置がある; THEN
  - MUST: その位置に、受け付ける形が判別できる情報を置く
  - PROHIBIT: 名前や役割を言い換えただけの記述を置く
- IF: 受け付ける値が有限の語彙である; THEN
  - MUST: 型でその語彙を表す
  - PROHIBIT: 説明の散文だけで語彙を伝える
- IF: 綴りがこのリポジトリの外で決められている値を扱う; THEN
  - MUST: 決めた側を名前に含める
    - 有限の値からなる語彙も、lint ルールの識別子も、綴りを決めた側が違えば別の語彙である
  - MUST: 決められた綴りのまま参照する
  - PROHIBIT: 自分の側で言い換えた語を発明する
  - IF: 決めた側を特定できない; THEN MUST: 特定できるまで名前を付けない
- MUST: 扱っている語彙をリポジトリのカタログへ登録する
  - 依存パッケージの公開型が既にその語彙を所有している場合の行き先は [0008. lint が型チェッカを起動し、読んだ型はメッセージにしか使わない](../engineering-decision-logs/0008-read-library-types-for-messages-only.md) が決めている

## 取り込まれる面に足すもの

公開した面は、外の利用者が読んだ時点で契約になる。畳むには利用者側の変更が要るので、何を載せるかの判断は内部の宣言より一段厳しい。取り込まれる面で問われるのは二つで、既に公開しているものから導けないことと、いま実際に呼んでいる経路があることである。

- IF: 公開する面に何かを足す; THEN
  - MUST: 同じ面が既に公開しているものと、利用者が既に依存している契約だけでは導出できないことを確かめる
  - PROHIBIT: 導出できるものを足す
    - 足した面が実際に使われているかを機械に見張らせる形は [0018. 公開面を実際に使われている分だけにし、機械に見張らせる](../engineering-decision-logs/0018-narrow-the-export-surface-to-what-is-used.md) にある
- IF: パッケージの公開エクスポートを変える; THEN MUST: エントリと消費側を同じ変更で更新する
- IF: 呼び出し側から使える口をインターフェースに足す; THEN
  - MUST: 今それを呼んでいる、テストではない経路を示す
  - PROHIBIT: 将来使う見込みを利用者の提示として扱う
- IF: テストからしか import されていない export がある; THEN
  - MUST: 消す
  - IF: 消せない; THEN MUST: その振る舞いを、利用者が実際に通る経路越しに検証する形へ書き換える

## 実行が外へ出す面に載せるもの

実行が外へ出すのは、CLI が標準出力に出す形と、lint ルールが出す報告である。どちらも読み手が機械であることがあり、そこに載せた値の形と、その値をどう見せるかを誰が決めるかが、別々に問われる。

- IF: 特定の利用者に向けてまとめた面を作る; THEN
  - MAY: 載せる事実とその粒度を選ぶ
  - PROHIBIT: 利用者の側の見せ方まで決める
- PROHIBIT: 出力の見せ方を契約に載せる
  - 契約になれるのは、ルール名と報告の識別子のように、言い回しを変えても同じものを指す綴りだけである
- IF: 失敗や結果を外向きの表現へ移す; THEN
  - MUST: 終了コード・報告の書式・利用者に見せる文言への変換を、ちょうど一箇所の境界で行う
  - PROHIBIT: 失敗そのものに外向きの表現を持たせる
- IF: ある値の解決に、利用者から到達できない状態が要る; THEN MUST: 解決した後の値を載せる
  - 走査で見つかったファイルの一覧、カタログが解決した所有者、依存の型から収穫した語彙は、名前のように見えても利用者には事実である
- IF: 解決した後の値と、その材料の両方が利用者に要る; THEN MAY: 両方載せる

## コードの傍に残したい記述

コードの傍に書き残したくなった内容は、まず所有者を決める。コードの中に残せる形そのものは [0005. コメント構文に残すのは機械が読む宣言だけにする](../engineering-decision-logs/0005-reserve-comment-syntax-for-machine-read-declarations.md) が絞っているので、ここで決めるのは絞られた後の行き先である。

判断の根拠については、コミットメッセージの本文と意思決定の記録のどちらへ残すかを [AGENTS.md](../../AGENTS.md) が持つ。この節が足すのは、行き先が決まった後にその根拠をどの単位へ入れるかだけである。

- IF: 書き残したい内容がある; THEN MUST: それが現在の姿と一度きりの決定のどちらを述べているかを先に判定する
  - 現在の姿はコードが変われば一緒に変わり、一度きりの決定は決めた時点に固定されて動かない
- IF: 内容が現在の姿を述べている; THEN
  - MUST: 識別子・型・テストのいずれかで表現する
  - IF: 三つのどれでも表現できない、公開する契約の説明である; THEN
    - MUST: その契約を所有するタグの下に置く
      - タグ配下に何を書いてよいかは [0018. 公開面を実際に使われている分だけにし、機械に見張らせる](../engineering-decision-logs/0018-narrow-the-export-surface-to-what-is-used.md) が確定させている
    - PROHIBIT: どのタグにも属さない位置に置く
  - IF: 三つのどれでも表現できない不変条件である; THEN MUST: それを所有する規範文書へ置く
- IF: 内容が判断の根拠である; THEN
  - MUST: 根拠を、それが説明している判断と同じ変更の単位に入れる
  - PROHIBIT: 複数の判断の根拠を、対象から離れた一箇所へまとめる
    - 根拠を、説明している行から離さないことは [no-detached-rationale--comment-at-explained-line](../../packages/dont-review-it/docs/lint/no-detached-rationale--comment-at-explained-line.md) が見ている
- IF: 根拠に書きたいのが、その作業をしている最中に分かったことである; THEN
  - MUST: 分かった制約の側を書く
  - PROHIBIT: どうやって気付いたかを根拠に置く

## 生成器が吐くコード

生成物を直接編集せずに源を直すこと、そこから外れていないことを検査に載せることは [強制の機構](enforcement.md) が持つ。ここで決めるのは、生成器が何を担い、何を担わないかである。

- IF: 生成器がコミット対象のソースを吐く; THEN
  - MUST: 生成器には意味のある出力だけを担わせる
  - MUST: 体裁の正規化をリポジトリのフォーマッタに任せる
    - 整形の所有者を一つにする形は [0020. ルールが要求する import の並びを整形器に出力させる](../engineering-decision-logs/0020-let-the-formatter-produce-the-import-order-the-rule-demands.md) にある
- IF: 再生成した出力とコミット済みの出力を比べる; THEN MUST: 比較の前に両方を同じ整形の契約で正規化する
- IF: 生成物が、このリポジトリの別の場所にある宣言をそのまま書き出したものである; THEN MAY: 生成物の側に、コードの傍に残す記述の規則を課さない

## 判断が割れたとき

- IF: 拡張点を先に用意したい要求と、今の呼び出し元を示す規則が衝突する; THEN MUST: 後者を採る
- IF: 失敗を表に出すことと、代替値で続けることが衝突する; THEN MUST: 表に出す側を採る
- IF: 単一の定義とテストの読みやすさが衝突する; THEN
  - MUST: テストの側の基準に従う
  - PROHIBIT: 独立した仕様どうしに単一の定義を当てる
    - テスト側で重複を残してよい条件は [テスト](tests.md) が持つ
- IF: 記録の完全性と機微な値を落とすことが衝突する; THEN MUST: [秘密と権限](secrets-and-permissions.md) の順位に従う
- IF: 特定の利用者向けにまとめた面と、見せ方を契約に載せない規則が衝突する; THEN MUST: 面が事実を選び、利用者がその表し方を選ぶ形に切り分ける
- IF: 記録の経路を一本に保つことと、記録を増やすことが衝突する; THEN MUST: 経路を一本に保つ側を採る

どちらとも決められないときは、後から戻せる側へ倒す。足さなかったものは後から足せるが、公開した面と付けてしまった名前は畳むのに利用者側の変更が要る。

- IF: 型の精度を落とすか境界で検証を足すかを判断できない; THEN MUST: 検証を足す側へ倒す
- IF: その値の綴りを決めた側を特定できているかどうかを判断できない; THEN MUST: 名前を付けずに保留する
- IF: その注入境界が正当かどうかを判断できない; THEN MUST: 足さない側へ倒す
- IF: そのフィールドが欠けるケースを挙げられるかどうかを判断できない; THEN MUST: 必須の側へ倒す
- IF: 足そうとしている値が既存の公開物から導出できるかどうかを判断できない; THEN MUST: 載せない側へ倒す

## 機械が判定できる形

この領域で機械が判定できるのは、書き方の違いが構文の違いとして現れる性質である。`packages/dont-review-it` のルールがこれらを見ており、個々のルールの文書は `packages/dont-review-it/docs/lint/` にある。以下は例であって、この領域を見ているルールの全部ではない。

- [no-twin-declaration--merge-into-one-owner](../../packages/dont-review-it/docs/lint/no-twin-declaration--merge-into-one-owner.md)
- [no-double-type-assertion--declare-the-real-type](../../packages/dont-review-it/docs/lint/no-double-type-assertion--declare-the-real-type.md)
- [no-discarded-failure--receive-and-surface-it](../../packages/dont-review-it/docs/lint/no-discarded-failure--receive-and-surface-it.md)
- [no-logged-and-continued-failure--stop-or-recover](../../packages/dont-review-it/docs/lint/no-logged-and-continued-failure--stop-or-recover.md)
- [no-local-finite-value-set--use-or-register-canonical-values](../../packages/dont-review-it/docs/lint/no-local-finite-value-set--use-or-register-canonical-values.md)
- [require-re-export-only-files--move-declaration-to-owning-module](../../packages/dont-review-it/docs/lint/require-re-export-only-files--move-declaration-to-owning-module.md)

落とせるのは形であって判断ではない。どの型がその場で最も精密かも、名前がその値の綴りを決めた側を含んでいるかも、どの語彙をカタログへ最初に登録するかも、構文を見るルールでは決まらない。

検査が有効なときに人が重ねて見るかどうかは [中核原則](principles.md) が持つ。報告だけを消す書き換えをどう扱うかは [レビューの指摘](review-findings.md) が持つ。
