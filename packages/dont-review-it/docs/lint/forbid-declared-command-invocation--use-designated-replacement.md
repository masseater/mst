# forbid-declared-command-invocation--use-designated-replacement

## 何を検出するか

宣言で退けたコマンドが、子プロセスとして起動されること。

判定の入口は、子プロセスを起動する API の呼び出しである。どの API が起動を行い、その実行対象がどの引数に来るかは表で持つ。表の 1 行は「モジュール指定子・そのモジュールが公開する名前・実行対象の引数位置・その引数が 1 つのコマンド名を持つのかコマンド行を持つのか」の 4 つで書く。既定の表は実行環境の子プロセスモジュールと、広く使われている 2 つの起動ライブラリを覆う。

**呼び出しの照合は綴りではなく束縛で行う。**`exec` という名前の呼び出しがすべて起動とは限らないため、その名前がどのモジュールの何に束縛されているかを解決してから表に当てる。解決するのは、名前付き import、既定 import と名前空間 import 越しのメンバー参照、同期要求からの分割束縛、そして起動 API を引数に取る呼び出しで作られたラッパである。正規表現の照合や、同じ名前を持つ自前の関数は起動として扱われない。

実行対象の引数は畳み込んでから照合する。書き出された文字列、埋め込みがすべて畳み込めるテンプレート、文字列同士の連結、同じファイルで `const` に束縛された値が畳み込みの対象になる。

コマンド行を持つ引数と、ランナーを実行対象に置いた起動は、行としてトークンに分けてから照合する。照合の規則は 1 つで、次のとおりである。

- 行の先頭、または区切り（空白・セミコロン・パイプ・論理演算子・括弧・改行）の直後にある語だけをコマンドの位置とみなす
- 先頭に置かれた環境変数の束縛は読み飛ばす
- 一時実行のランナーとシェルの `-c` は前置きとして読み飛ばし、その後ろに置かれた語をコマンドとみなす。前置きの直後に並ぶフラグも読み飛ばす
- ランナーに渡された指定子はバージョンを落として照合する。スコープ付きの名前はスコープを保つ
- 取得アドレスは、パス区切り・スコープ記号・クエリ記号で要素に分け、要素の完全一致だけを見る

報告は 3 つに分かれる。退けたコマンドの起動、実行対象が静的に決まらない起動、そして実行対象が実行時にしか決まらないコマンド行である。後ろの 2 つは「禁止に当たった」ではなく「照合が成立していない」を伝えるもので、文面を分けてある。実行対象が実行時にしか決まらない行とは、取得した内容をシェルに渡す形、内容を評価する形、コマンドの位置が置換で書かれた形である。

宣言の登録そのものの不備も報告する。理由文を持たない解除エントリ、宣言に存在しない名前を指す解除エントリ、理由文を持たない位置の登録の 3 つで、いずれも解析対象のファイルに違反が無くても出る。

次のものは違反ではない。

- 起動 API を import すること自体。何を起動するかだけを見る
- 退けた名前が、実行対象ではなくファイルパスや引数の一部として現れていること
- 宣言に載っていないコマンド。危なそうなコマンドを推測しない
- 畳み込んだ結果が宣言のどの名前とも一致しない実行対象
- 宣言が空、または与えられていない場合。照合すべきものが無い

## なぜそれが要るか

観測される事象は、依存欄からもソースの import からも消えたツールが、実行ログには現れることである。

import の禁止はモジュールグラフを、マニフェストの禁止は宣言テキストを見ており、子プロセスの起動はそのどちらにも現れない。起動 API に渡された文字列は、その位置ではただの引数であって、モジュール解決にもマニフェストにも触れない。

ツールを退けた理由は呼び出し方に依存しない性質を持つ。後継が実行環境に取り込まれた、保守が止まっている、配布経路が信頼できない、といった判断は、import であっても CLI であっても同じように成立する。それなのに強制は呼び出し方ごとに用意しないと届かない。**2 経路だけを塞ぐと、3 つ目が「唯一残った書ける形」として選ばれる。**禁止が強いほど、残った経路に圧力が集まる。

「型付きの API があるならサブプロセスを使うな」という一般規律を待っていても、この空白は埋まらない。同じ処理を型付き API で書けるかどうかは対象ごとに別の知識が要り、機械が持てる判断ではないからである。持てる形に落とすと「退けた名前と、代わりに何をするかの指示文」の 1 行になる。一般規律の有無に関わらず、落とせる形で落としておけば空白は残らない。

## どう直すか

報告に出た指示文が名指しするコマンドか API に置き換える。指示文は宣言の行が持っているので、置き換え先は呼び出しごとに選び直さなくてよい。

実行対象が静的に決まらないと報告された場合は、対象を名前で書く。分岐で候補が変わるなら分岐ごとに起動を書き、名前から実装を引く表があるならその表を読む側に移す。

コマンド行が読めないと報告された場合は、取得と実行を分ける。取得した内容をそのままシェルに渡す形をやめ、実行するコマンドを名前で書いて引数を渡す。

そのコマンドを使い続ける必要があるなら、呼び出し位置ではなく設定層で解く。宣言の行を外す解除エントリを理由文つきで置くか、その位置を例外として登録して理由文を書く。どちらも差分に現れ、消費側から一覧として読める。

## 禁じる回避策

- 実行対象を変数に組み立てて渡すこと。実行対象が静的に決まらないという報告が出る
- 起動 API を薄く包んだ関数を作り、そこにだけ退けた名前を書くこと。ラッパは束縛として解決されるので、包んでも同じ位置で報告される。名前を引数として渡す形にしても、包んだ側の実行対象が畳み込めなくなるだけで、その形が報告になる
- 一時実行のランナーを前に置くこと。ランナーは前置きとして読み飛ばされ、後ろの名前が照合される
- 退けたコマンドを起動するだけのシェルファイルを挟むこと。シェルファイルの本体も同じ宣言で照合される供給元である
- 抑制コメントで黙らせること。例外の置き場は設定であって、ソースの行ではない
- 理由文を空にしたまま解除エントリや位置を登録すること。免除されないうえ、登録そのものが報告される

## オプション

```jsonc
[
  "error",
  {
    "declared": [{ "name": "lerna", "substitute": "ワークスペースのタスクランナーを使う" }],
    "withdrawn": [{ "name": "gulp", "grounds": "配布ジョブがこのコマンドだけを受け付ける" }],
    "spawnForms": [
      {
        "specifier": "node:child_process",
        "exported": "exec",
        "position": 0,
        "carries": "commandLine",
      },
    ],
    "exceptions": [{ "path": "apps/*/release-job/**", "reason": "実行対象は公開したタグが決める" }],
  },
]
```

`declared` は「退ける名前」と「代わりに何をするかの指示文」を 1 組で持つ行の列である。**この配列は import を見る検査とマニフェストを見る検査が読むものと同じ型定義で、同じ合成規則に従う。**規則は「既定の一覧を出発点とし、消費側の指定はそこへ加える」であり、置換ではない。指示文は報告にそのまま埋め込まれるので、名詞ではなく行動として書く。

`withdrawn` は既定の一覧から行を外す解除エントリである。`grounds` が空の行は登録として不正になり、既定にも消費側の宣言にも存在しない名前を指す行は死んだ解除として報告される。

`spawnForms` は起動 API の表を丸ごと差し替える。`carries` は `name`（1 つのコマンド名）か `commandLine`（コマンド行）のどちらかで、`position` を省略すると先頭の引数を読む。

`exceptions` は、この検査を適用しない位置とその理由文を 1 組で持つ行の列である。`path` はグロブで、`reason` が空の行は登録として不正になる。

既定の `declared` は空である。何を退けるかは、公開されている技術情報だけを根拠に説明できる範囲でリポジトリの設定が決める。

## この検査が引き受けないもの

- 同じ処理を型付き API で書けるかどうか。それは `substitute` として人が書く。機械が保証するのは、そのコマンドが起動されないことだけである
- ソース以外に書かれたコマンド文字列。CI のワークフロー定義、リポジトリ内のシェルスクリプト、パッケージマニフェストのスクリプト欄、文書のコードブロックは、静的解析器が開かないため本ルールの入力に現れない。**同じ宣言でこれらを照合する入口は別に要る。**行の照合規則をこのルールが独自に持たず、共有の実装として置いてあるのはそのためで、その入口が置かれたときに同じ実装を読ませる
- 実行対象がファイルパスとして書かれた起動。照合はトークンの完全一致で、パスの一部に現れた名前は拾わない
- リポジトリの外で定義された実行。CI プロバイダの提供機能や、外部で作られたコンテナイメージに焼かれた起動は入力に現れない
- そのコマンドがマニフェストに宣言されていることと、そのモジュールが import されていること。前者はマニフェストを読む検査が、後者は import を読む検査が受け持つ。3 本が同じ宣言を読むことで、引き込まれる・読み込まれる・起動されるの 3 経路が閉じる
