# require-re-export-only-files--move-declaration-to-owning-module

## 何を検出するか

ファイル名が `index.ts` のファイルの、Program 直下にある文のうち、再 export ではないものすべて。

再 export として通すのは次の 2 つだけ。

- `export ... from "..."`（`source` を持つ `ExportNamedDeclaration`）。`export type { T } from "..."` も `export { default as X } from "..."` も含む
- `export * from "..."` / `export * as ns from "..."`（`ExportAllDeclaration`）

これ以外は、宣言も、import も、式文も、`export default` も、`"use strict"` のようなディレクティブも、すべて報告する。判定は「再 export の形かどうか」だけで行い、違反の側を列挙しない。

報告位置は違反している文そのもの。1 ファイルに複数あれば、それぞれ個別に報告する。

対象の判定はファイル名の完全一致で行う。`print-index.ts` のように `index.ts` で終わるだけの名前は対象にならない。`index.tsx` / `index.mts` / `index.js` も対象外。

報告は 2 種類ある。

- `declarationInPublicSurface`: 宣言や実行される文。所有すべきモジュールへ移すことを指示する
- `forwardingWithoutSource`: import 文、および `source` を持たない `export { x };`。どのモジュールから来たかを export 文自身に書くことを指示する

`import { total } from "./total.ts";` と `export { total };` の 2 文に分けて書いた場合は、両方の文が報告される。1 つの問題に対して 2 件出るが、直すべき文が 2 つあるので集約しない。

## なぜそれが要るか

このリポジトリでは、宣言の所有者はファイル名で決まる。`total` がどこのものかを知りたければ `total.ts` を開けばよく、その対応は探さなくても分かる。

`index.ts` はこの対応の外にある。名前が中身を指しておらず、公開面という役割だけを持つ。ここに宣言が 1 つでも混ざると、その宣言だけは所有者がファイル名から決まらなくなる。読み手は「`index.ts` にあるものは他のファイルにある」という前提を捨てて、公開面も宣言の置き場として毎回疑うことになる。前提が壊れるのは混ざった宣言 1 つの話ではなく、公開面全体に対してである。

import と `source` を持たない export を許さないのも同じ理由による。`export { total } from "./total.ts";` は、公開されている名前と、それを所有するモジュールを 1 文で言い切る。2 文に分けると、公開面が何を出しているかを読むのに、別の文まで戻って結び直す必要が出る。この結び直しは、export される名前が増えるほど効いてくる。

副作用のための import も同じ扱いになる。公開面は「何が公開されているか」だけを述べる場所であり、import した時点で何が起きるかを述べる場所ではない。

## どう直すか

宣言が報告された場合、その宣言を所有するモジュールへ移し、`index.ts` からは `export ... from` で再 export する。移す先のファイル名は、その宣言の名前に対応させる。

import と `source` を持たない export が報告された場合、2 文を `export ... from "..."` の 1 文にまとめる。

副作用のための import が報告された場合、その副作用を必要としているモジュールへ移す。公開面を経由して副作用を効かせているなら、効かせたい場所が別にあるはずで、そこが置き場になる。

## 禁じる回避策

- ファイル名を `index.ts` 以外に変えて検出を外す。公開面としての役割は変わらないまま、`index.ts` という手がかりだけが失われる
- 宣言だけを別ファイルに切り出し、そのファイルが `index.ts` からしか使われない状態にする。ファイル名が所有者を指していないので、`index.ts` に置いたときと同じことが起きる
- `import` と `export { x };` の 2 文に分けて、宣言をどちらでもない位置に置く。両方の文が報告される
- 宣言を `export default` にして公開面に残す。再 export の形ではないので報告される

## オプション

取らない。有効か無効かだけを設定側で決める。
